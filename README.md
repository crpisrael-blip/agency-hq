# Agency HQ — מרכז הבקרה של בית התוכנה

מערכת-על לניהול בית התוכנה/הייעוץ שלך. לא מערכת ללקוח — אלא המערכת שמנהלת **אותך**: את כל הלקוחות, את המערכות שאתה מפתח לכל אחד מהם, את התזרים שלך, ואת מודלי החיוב.

הבנויה על אותו stack ענן מוכח: **Cloudflare Pages** (אירוח) + **D1** (SQLite) + **Hono** (API) + **Drizzle** (ORM). עברית מלאה RTL.

הזרימה: אתר סטטי (`/public`) → API (`/functions/api`) → D1.

## מה יש במערכת

| מסך | מה הוא עושה |
|-----|-------------|
| **לוח בקרה** | התמונה הכוללת: MRR, ARR, צנרת, לקוחות פעילים, מערכות חיות, תמהיל הכנסה לפי מודל חיוב |
| **לקוחות** | כל עסק שאתה משרת — כרטיס 360 עם מערכות, התקשרויות, מרכזי רווח, בריאות לקוח ומסע הלקוח |
| **מערכות** | כל מערכת מידע שאתה מפתח: סטטוס, התקדמות %, stack, כתובת חיה, repo |
| **התקשרויות** | מודל החיוב מול כל לקוח — מה שמזין את ה-MRR והתזרים |
| **מחשבון חיוב** | ⭐ כל המשתנים במקום אחד. משווה 6 מודלי חיוב חיים (חד-פעמי / ריטיינר / שעתי / אחוז ממחזור / מבוסס-ערך / היברידי), מחשב רווח, שוליים, תעריף אפקטיבי לשעה ונקודת החזר. שומר תרחישים ויוצר התקשרות בלחיצה |
| **תזרים** | תחזית חודשית (6/12/24 ח') המשלבת הכנסות אוטומטיות מההתקשרויות הפעילות + תנועות ידניות (הוצאות, כלים, קבלני משנה), עם יתרת פתיחה ומאזן מצטבר |
| **מרכזי רווח** | רעיונות עסקיים והכנסות חדשות — עם פוטנציאל חודשי, סבירות וערך משוקלל |
| **תהליכים** | תהליכי עבודה, מסעות לקוח ונהלים (SOP) שאתה בונה — עם שלבים ואחראים |
| **מתודולוגיה** | ⭐ ספריית פורמטים מקצועיים לכל מסע המוצר (אפיון → הצעה → פיתוח → QA → אבטחה/פרטיות → עלייה לאוויר → מסירה → תחזוקה → ייעוץ). כל פורמט ניתן לעריכה, ואפשר "להחיל" אותו על לקוח/מערכת כדי שיהפוך למהלך חי עם צ'ק־ליסט ומעקב התקדמות. ראה `docs/METHODOLOGY.md` |
| **משימות** | לוח קנבן: לביצוע / בעבודה / הושלם |

## מודל הנתונים (D1 / Drizzle)

`clients` · `systems` · `engagements` · `scenarios` · `cashflow` · `profit_centers` · `processes` · `playbooks` · `playbook_runs` · `tasks` · `settings` · `admin_sessions`

הסכמה המלאה: `src/db/schema.ts`. המיגרציות: `migrations/`.

### לב החישוב — מודלי חיוב

הערך החודשי (MRR) של כל התקשרות מחושב לפי מודל החיוב שלה (`src/api/engagements.ts` → `engagementMonthly`):

- **ריטיינר / מבוסס-ערך** → הסכום החודשי הקבוע
- **שעתי** → תעריף שעה × שעות בחודש
- **אחוז ממחזור** → מחזור הלקוח × האחוז
- **חד-פעמי** → 0 חודשי (רק מקדמת הקמה)
- **היברידי** → סכום כל הרכיבים

תחזית התזרים (`src/api/finance.ts` → `/finance/forecast`) משלבת את כל ההתקשרויות הפעילות עם התנועות הידניות למאזן מצטבר חודשי.

## הקמה חד-פעמית (Cloudflare)

1. פותחים חשבון חינמי ב-Cloudflare.
2. יוצרים בסיס נתונים D1 ומעתיקים את ה-`database_id` ל-`wrangler.toml`:
   ```bash
   npx wrangler d1 create agency-hq-db
   ```
3. יוצרים פרויקט Pages ומחברים אותו ל-repo הזה ב-GitHub (Build command ריק, Output directory: `public`).
4. מוסיפים binding ל-D1 בשם `DB` בהגדרות ה-Pages.
5. מריצים את המיגרציות: `npm run db:migrate:remote`.

בכניסה הראשונה המערכת תבקש להגדיר **קוד גישה** (4 ספרות ומעלה) — הוא נשמר מגובב (SHA-256).

## פיתוח מקומי

```bash
npm install
npm run db:migrate:local      # יוצר טבלאות ב-D1 מקומי
npm run dev                    # http://localhost:8790
```

## עדכונים

כל דחיפה ל-`main` ב-GitHub → Cloudflare Pages בונה ומעלה גרסה חדשה אוטומטית (ראה `.github/workflows/deploy.yml`; דורש את ה-secret `CLOUDFLARE_API_TOKEN` ואת `CLOUDFLARE_ACCOUNT_ID`).
