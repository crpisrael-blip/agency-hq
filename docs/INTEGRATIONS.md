# חיבור מערכות ו-API — מדריך מעשי

> מלווה את הפורמטים "חיבור אינטגרציה" ו"מפרט אינטגרציה" במסך **מתודולוגיה**.
> המטרה: להפוך "לחבר API" ממשהו מפחיד לתהליך מסודר וחוזר.

---

## הרעיון בגדול

הלקוח כבר עובד עם כלים — הנהלת חשבונות, סליקה, וואטסאפ, יומן. המערכת שלך היא עוד "אי".
**אינטגרציה = גשר בין האיים** כדי שמידע יזרום לבד, במקום שמישהו יעתיק ידנית.

**API** הוא ה"מלצר" של המערכת השנייה: אתה לא נכנס למטבח שלהם (מסד הנתונים), אלא נותן הזמנה מסודרת ("הפק חשבונית על 500₪") ומקבל תשובה ("מספר 1234"). התיעוד (Documentation) הוא התפריט — מה מותר לבקש ואיך.

---

## שני הכיוונים — הלב של הנושא

| כיוון | מה זה | דוגמה |
|---|---|---|
| **קריאה ל-API (אנחנו יוזמים)** | המערכת שלך אומרת "עשה X" | סיום ניתוח → קריאה ל-API של הנה"ח: "הפק חשבונית" |
| **Webhook (הם דוחפים אלינו)** | המערכת השנייה מודיעה שקרה משהו | הסליקה שולחת "התשלום אושר" → אנחנו מעדכנים סטטוס |

Webhook = "אל תתקשר אלינו, אנחנו נתקשר אליך" — עדיף על שאילה חוזרת, כי הוא מיידי ויעיל.

---

## כלל הזהב עם הסטאק שלך

**לעולם לא לקרוא ל-API חיצוני מהדפדפן.** כל חיבור דורש מפתח סודי; אם הוא בקוד של הדפדפן — אפשר לגנוב אותו.

הפתרון — שכבת ביניים בשרת, שכבר יש לך:
- **Supabase → Edge Function**
- **Cloudflare → Worker** (כמו ה-API של agency-hq)

הזרימה: `דפדפן → הפונקציה שלך בשרת (מחזיקה את הסוד) → ה-API של הצד השלישי`. הדפדפן אף פעם לא רואה את המפתח.

---

## אבטחה וסודות

- **מפתח API / טוקן** = הסיסמה של החיבור. נשמר רק ב-Secrets / Environment Variables — לא בקוד, לא ב-Git.
- **אימות webhook נכנס:** מי ששולח "התשלום עבר" — לוודא בחתימה/סוד משותף שזה באמת הצד הנכון, אחרת אפשר לזייף.
- **הרשאת מינימום:** קח מפתח שמורשה רק לפעולה שצריך, לא מפתח-על.

---

## פרטיות — קריטי

ברגע שמידע יוצא מהמערכת שלך לצד שלישי, זה אירוע פרטיות:
- **בסיס חוקי** לשליחת מידע אישי, וציון במדיניות הפרטיות.
- הספק השלישי הופך ל**קבלן משנה** → מופיע ב-**DPA**.
- **מינימיזציה:** שלח רק את ההכרחי (לחשבונית — שם וסכום, לא מידע רפואי).

---

## מה לאסוף מהלקוח לפני שמתחילים

1. עם איזו מערכת מחברים — שם מדויק + חבילה/גרסה.
2. האם יש לה API בכלל? (בלי API — אין חיבור אוטומטי.)
3. קישור לתיעוד ה-API.
4. מי מפיק את מפתח ה-API (בד"כ הלקוח).
5. מה בדיוק צריך לזרום — אירוע מפעיל → פעולה.
6. יש סביבת בדיקות (Sandbox)?
7. עלות שימוש אצל הספק השלישי?

## נוף הכלים בישראל (למצוא מהר את ה-API הנכון)

- **הנה"ח / חשבוניות:** Morning (חשבונית ירוקה לשעבר), iCount, ריווחית, EZcount.
- **סליקה:** Cardcom, Tranzila, PayPlus, Grow/Meshulam. (Bit — בעיקר דרך מסלקה.)
- **הודעות:** וואטסאפ עסקי דרך ספק (GreenAPI, 360dialog, Twilio); SMS דרך 019/Inforu.
- **יומן ומייל:** Google Calendar API; מייל דרך Resend/SendGrid.
- **בינלאומי:** Stripe — סטנדרט הזהב לתיעוד ואיכות.

## הזווית העסקית (כאן אתה יועץ)

- **אינטגרציה = מרכז רווח.** עבודה נפרדת מה-SOW → מתומחרת בנפרד. תעד במסך "מרכזי רווח".
- **תחזוקה בריטיינר:** API של צד שלישי משתנה ונופל — התחזוקה שייכת ל-SLA, לא לחד-פעמי.
- **מכור ערך, לא טכנולוגיה:** לא "אחבר API" אלא "תפסיק להקליד חשבוניות — חצי שעה ביום".

---

## שלוש טעויות נפוצות

1. **סוד בדפדפן** → דליפה. תמיד דרך שרת.
2. **בלי Sandbox** → חיובים/חשבוניות אמיתיים בטעות.
3. **בלי טיפול בכשל** → הצד השלישי נפל והמערכת בולעת בשקט. תמיד: לוג + ניסיון חוזר + התראה.

# חיבור לקמפיינים ברשתות חברתיות

מקרה מיוחד וחשוב של אינטגרציה — חיבור מודעות (פייסבוק/אינסטגרם/גוגל) למערכת של הלקוח.
רלוונטי כמעט לכל לקוח שמפרסם. ראה גם הפורמט **"חיבור קמפיינים ולידים"** במתודולוגיה.

## ארבעת הכיוונים

| כיוון | מה זורם | הבעיה שנפתרת |
|---|---|---|
| **לידים פנימה** | מי שהשאיר פרטים במודעה → למערכת | לידים לא הולכים לאיבוד / לא מקלידים ידני |
| **אירועים החוצה** | "הליד הפך ללקוח" → חוזר לפלטפורמה | האלגוריתם לומד להביא לקוחות, לא קליקים |
| **דוחות פנימה** | ביצועי הקמפיין → ללוח שלך | לראות מה עובד במקום 10 מסכים |
| **קהלים החוצה** | רשימת לקוחות → רימרקטינג/קהל דומה | לפרסם למי שקנה / לדומים לו |

**הכיוון החשוב ביותר — "סגירת הלולאה":** חיבור ההוצאה על פרסום ללקוח משלם במערכת. זה מה שנותן ללקוח **ROI אמיתי** ("מודעה עלתה 500₪, הביאה 3 לקוחות ששילמו 4,000₪") — וזה מה שהופך אותך ממפתח ליועץ.

## הכלים

- **Meta (פייסבוק/אינסטגרם):** Graph + Marketing API, דרך Business Manager. Lead Ads (webhook leadgen), **Pixel + Conversions API (CAPI)**, Custom Audiences.
- **Google Ads:** Offline Conversion Import + Google Ads API.
- **גישה:** Meta App + אימות עסק + App Review — תהליך של ימים, לתכנן מראש.
- **התחלה חכמה:** מחבר no-code (Make/Zapier) למשיכת לידים לפני API מלא.

## פרטיות (קריטי)

העלאת רשימת לקוחות לקהלים = העברת מידע אישי לחו"ל ולצד שלישי:
- **הסכמה שיווקית** מהלקוח הקצה, ועדכון מדיניות הפרטיות.
- Meta דורשת העלאה **מגובבת (SHA-256)**.
- Meta = **קבלן משנה** ב-DPA. **מינימיזציה** תמיד.

## הזווית העסקית

מרכז רווח דו-שימושי: אותו חיבור נמכר לכל לקוח שמפרסם (מכון יופי, צימר, חדר כושר).
מוצר אחד, הרבה לקוחות — הקמה + ריטיינר תחזוקה.
